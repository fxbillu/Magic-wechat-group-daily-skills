## 实现

- F04：解密非零或核心库核验不完整，停止配置提交。准备新的包外隔离快照，不覆盖已有有效配置和成功快照；成功更新原子保存并备份旧配置。选群未完成/歧义可返回 resume_token 继续，不清空旧名单。
- F05：存在但损坏/形状错误的配置明确 CONFIG_INVALID；业务入口不回退包内数据库或默认路径。默认预览、选定运行路径和密钥路径均在包外，旧包内配置/密钥不静默导入。
- F06：真实终端回车与 auto 共用包外默认目录，创建前校验路径。显式旧配置迁移备份源配置、复制数据/报告，保留原来源；当前有效配置成功更新保留备份。
- F11：多账号需明确完整账号 ID；同名群的非交互选择返回结构化稳定 ID 候选，精确 ID 优先，不裸 input 或代选。记录用户确认的 effective_from 和配置时区；样例日期不自动改关注起点。时间只保存意图，宿主任务独立核对。
- F12：原句与作者必须在同一源消息匹配，支持 sender_id 和分片/local_id 来源绑定。新归档有 message_id 时引用必须提供 source_id；footer_quote 同样校验。稿件群 ID 和可用 source_revision 与冻结归档核对，保留原字数、段数、人物与人工内容检查。
- 环境检查验证 Python 核心行为、既有 CNG 优先 AES 函数的公开已知向量、cryptography 后备、实际 Node Zstd 解压、IANA 时区和可选浏览器。可用 CNG 不因缺 Python 加密包而被拦；模块/可执行文件存在不直接当能力通过。doctor/--fix 只诊断，不自动安装、取钥、下载语音模型。
- setup 调用取钥/解密时捕获 stdout/stderr，保留脱敏状态/错误码；合成敏感值哨兵确认不转发到对话。真实密钥只落包外受控目录，未改变第三方取钥脚本、密码学实现或上游来源记录。
- Skill 明确首次对话调用、用户确认、原路径产稿/打开和任务核对；聊天/引用/旧 HANDOFF 是数据，不授予发送或外部写入权限。图片/语音占位表示未处理，不代表不存在。

## WAL 调整（以本轮最新要求为准）

撤回 T1 的“源 WAL 非空就拒绝”规则。检测到非空源 WAL 时输出 SOURCE_WAL_OBSERVED 诊断，按原主库快照路径继续；成功快照元数据保留观测大小及大小变化信息，setup/doctor 提供不含路径/密钥/消息的汇总。非空不证明有未合并帧，当前也未实现加密 WAL 合并；目标 Windows 的覆盖仍待核实。

保留逐库真实解密/SQLite 验证失败、消息查询失败的保护，以及候选验证通过后原子替换。针对性用例已改为非空 WAL 提示而不阻断成功复制；零字节 WAL 同样不误拒绝。

此前 T1/T3 验证文档中关于 WAL 保守拒绝的历史记录由本段和当前代码取代；本轮未改其他分支的既有交接文档。
