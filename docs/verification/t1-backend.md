# T1 后端验证与集成交接

日期：2026-10-27（Asia/Shanghai）。票据：[T1：可靠采集指定群和日期并展示真实结果 #3](https://github.com/fxbillu/wechat-group-daily-skills/issues/3)。固定基线：`1bef2b65624f7f6dd7d4273ce30cfa4cc8bc2884`。

## 范围与实现

仅处理 T1 Python 后端及其公共 CLI / HTTP 验收。未修改前端、包构建器、共享契约、共享夹具、T0 测试、根工程文档或共享开发日志；主控集成时统一追加 `docs/dev-log.md`。

- 配置采集使用 `username`，不再把它转回展示名解析。素材、默认报告与元数据路径使用稳定 ID 的 SHA-256，避免同名、特殊字符归一及改名覆盖。
- 每条消息保留 `source_shard`；发送者 rowid 仅在本分片 Name2Id 中解析。无群表可正常跳过；分片损坏、查询和映射失败明确中止当前群日采集。
- 保存成功零消息、左闭右开目标区间、RFC 3339 观察时间和稳定素材版本。`compose.timezone` 存在时用于自然日边界，否则使用执行机时区并将 timezone 保持 null。
- 成功素材和最新采集尝试分别持久化。失败不覆盖已成功素材、索引消息或报告；首次失败也可以重建索引。读取入口提供 v1 `collection/report`；矩阵、日期、群历史及详情共用语义。
- 报告登记绑定稳定 ID 与 source_revision。重采保留已登记链接及元数据，相同素材版本不变；素材变化后旧 HTML 仍可打开并标记 stale。链接只在报告目录内的真实文件存在时返回；未生成 PNG 保持 null。
- 旧名称文件按自身 username 重建，不删除来源。已有规范 ID 文件优先；冲突旧副本或缺少身份的文件不会猜测归属，CLI 返回非零并要求用户选择。旧报告无版本证据时显示需要更新。
- 解密先写临时文件，经 SQLite 可读性与 quick_check 核验并关闭连接后原子替换。失败保留最后成功快照。schema v2 时间戳逐库记录 verified_at 与失败，只有所需核心库全部成功才能供完整采集；`--allow-stale` 不绕过覆盖错误，`--rebuild-stamp` 也不制造核验事实。

运行数据新增于包外数据目录：`collections/<date>/<id-hash>.json` 保存最新尝试；`report-records/<date>/<id-hash>.json` 保存报告链接、版本及展示元数据。成功素材的 collection 也保存在归档内。索引 schema version 仍为 1，不使 T0 合法索引因增加可选元数据而不可读。HTTP 请求不执行迁移或修复。

## 先红后绿证据

测试仅运行干净技能副本、隔离包外配置和合成 SQLite，无微信私聊或客户素材。

| 缺陷 | 公共入口的失败证据 | 修复后的观察 |
|---|---|---|
| F01 | 同名配置采集返回 2，两次名称解析都歧义 | 两群独立可读；改名与重建仍保留身份；特殊字符名称不覆盖 |
| F07 | 第二分片 rowid=1 的乙被 HTTP 显示为甲 | 两片各自显示甲、乙，并保留来源分片 |
| F03 | 一片损坏后 CLI 仍返回 0 并归档部分消息 | 非零退出；HTTP collection.failed / coverage.complete=false，保留上次完整消息 |
| F09 | 成功零消息返回 2，未落归档 | 返回 0；HTTP empty、计数 0、有目标范围，区别 not_collected 的 null 计数 |
| F02 | 部分解密失败已经破坏上一成功快照 | 候选失败不替换原库；后续 CLI 即使 allow-stale 也拒绝完整采集 |

另在公共入口验证：首次失败后重建仍可见；规范来源不被旧名称副本替代；报告同名身份、素材稳定版本、变化后 stale、HTML 可打开与重建恢复；素材画像 CLI 保持可用；未知身份资料保留且非零退出；非空和零字节 WAL 分别处理。

解密验收只将平台 AES 提供者替换为测试桩，包内解密/验证/发布/时间戳/采集/HTTP 代码均实际执行。合成 envelope 有真实 HMAC，但 AES 数据采用恒等变换，明确不能证明 Windows CNG、真实 SQLCipher 密文或真实取钥可用；测试不依赖额外 Python 包或安装加密依赖。

## WAL 与 Windows 真实取数限制

当前原有路线只复制与解密主库，**没有实现加密 WAL 合并**。若源库旁 `-wal` 在复制前或复制后检查时存在且长度大于零，明确拒绝该候选；零字节 WAL 不会仅因存在而被拒绝。主库复制期间不稳定、库页不完整、验证失败也拒绝。此行为表示无法证明覆盖时保守失败，不能称为处理好了实际加密 WAL。

普通已登录微信能否稳定取得已合并 WAL 的快照、复制期间 WAL 的实际变化、实际微信库结构及来源覆盖均尚未在 Windows 验证；该路线不能据此宣称每天可靠出报。Windows 验收前需要选择并实测可靠的库+WAL 快照/合并方案，或证明受支持场景能安全取得无未合并 WAL 的快照；不得通过忽略非空 WAL 宣布通过。本轮未安装任何依赖、未读取真实微信、未运行取钥程序。

同样待验证：真实模型稿件与来源核对、PNG、WorkBuddy 宿主任务回读及真实到点触发、第二台机器安装。跨层 #3 仍需主控连接真实后端与前端验收，未关闭 Issue，未合并、推送或发布。
