# 微信群日报开发主计划

日期：2026-10-26。主对话：**微信群日报｜主控与验收**。

**状态：用户已批准 T0–T5 拆分、依赖及公共 CLI / 真实 HTTP API 的验证方式，并授权发布任务。主规格与六张任务票已发布；T0 正在实施，产品整体尚未完成。三个可见开发对话将在 T0 共同基线完成后创建。**

本计划记录用户已确认的方向与执行方案。当前能力、缺陷与实际验证边界见[导入与闭环审查](../reviews/2026-10-26-import-review.md)；领域用语见[词汇表](../../GLOSSARY.md)。历史 HANDOFF 是来源材料，其“已完成”不能代替本次验收证据。

## 问题

用户希望在存放微信记录的 Windows 电脑上，让 WorkBuddy 每天整理多个关注群的聊天，按群形成独立日报，并按日期或群回看。朋友和团队伙伴拿到同一个干净 Skill 后，应能配置自己的微信账号、关注群和日报时间。

旧实现已具备采集、归档、模型写稿、检查、渲染和本地阅读能力，但新机器首次初始化、宿主定时任务、失败恢复与干净分发尚未闭环。审查还复现了影响群身份、数据覆盖、初始化结果、引文归属及浏览查询的缺陷。不能只改善页面后就把旧包交给别人使用。

## 方案

### 已确认的产品方向

- 首版服务于 Windows + WorkBuddy；每个人在自己的电脑安装，一次安装绑定一个由本人确认的微信账号。
- 首次使用由 **WorkBuddy 对话引导**：检查环境、确认账号、选择数据目录、选择关注群、设置时间。网页负责阅读日报和显示运行状态。
- 每个群、每个自然日形成独立日报；某天的多个关注群以列表汇总，支持继续进入某个群的历史。
- 前端继续使用 Impeccable，保留现有暖纸色、炭黑与少量砖红的阅读风格，以及本地 Vue 3、无 CDN 的实现。
- 最终交付为干净 Skill。代码可以替换并支持只读运行；配置有固定的包外发现位置，用户可以另选数据存放目录。
- 主对话负责计划、接口、依赖、集成和验收；开发分派到用户可见的新对话。

### 首次使用流程

1. 用户上传技能后，首次在 WorkBuddy 对话中调用时检测未配置并进入初始化，运行环境检查，分别报告必需能力与可选能力。不承诺上传事件本身会自动执行初始化。
2. 用户确认微信账号及外部数据目录；多账号、同名群均展示可区分的候选，不替用户猜测。
3. 读取所需核心库并核验覆盖，用户选择一个或多个关注群。失败时保留上次有效配置及可恢复进度。
4. 生成首份样例日报，建议先取昨天。当天无消息或不足成篇时明确说明，由用户确认是否改选有消息的日期。
5. 用户设置每天的触发时间，默认建议生成前一个完整自然日的日报。这里的时间是**开始执行的时间**，不是承诺日报完成的时间。
6. WorkBuddy 创建或核对自己的定时任务，回读任务身份、触发时间、目标日期规则和执行提示词。
7. 打开本地网页查看样例、关注群与任务状态；一次真实到点触发成功后，才标记自动运行已验证。

首次样例和任务登记可先完成；若真实触发尚未发生，应显示“已登记，等待首次定时运行”，不能显示为已经自动运行成功。多天漏跑先展示缺口，由用户选择补跑范围；不默认无限补跑，也不把旧配置中的“初始 7 天”视为已确认需求。

## 用户故事

1. 作为首次安装者，我希望 WorkBuddy 告诉我当前还缺什么及下一步，以便完成安装而不必阅读源码。
2. 作为有多个微信账号的用户，我希望确认本次使用的账号，以便日报不会读取错误账号的数据。
3. 作为用户，我希望选择自己的数据目录，以便代码升级和移除 Skill 时仍能保留日报与个人数据。
4. 作为用户，我希望从可区分的候选中选择多个关注群，以便同名、改名时仍能准确识别目标群。
5. 作为首次安装者，我希望先看到一份经过原文核对的可读日报，以便确认工具在本机可用。
6. 作为用户，我希望设定每日触发时间并看到任务实际登记结果，以便知道什么时候会开始执行。
7. 作为用户，我希望清楚区分未采集、无消息、素材不足和执行失败，以便不把数据遗漏误认为群里没有聊天。
8. 作为读报者，我希望按日期查看多个关注群的日报列表，也能查看一个群最近的日报，以便快速找到关心的内容。
9. 作为读报者，我希望用关键词、群和日期共同筛选历史记录，以便定位某次讨论及其日报。
10. 作为用户，我希望重新采集或补跑时保留已有可读日报，并看到它是否需要更新，以便重试不会造成内容丢失或状态混乱。
11. 作为遇到失败的用户，我希望看到失败步骤、可重试性和下一步，并选择补跑日期范围，以便恢复工作而不重复初始化。
12. 作为分享者，我希望交付一个不含本人账号、密钥、聊天和运行记录的包，朋友在另一台 Windows 上能独立初始化并升级，以便放心在私人范围内使用。

## 实现决定

以下是本轮方案边界；字段的具体机器名称、配置发现位置与迁移细节在 T0 固化，并作为前后端共同契约。

### 职责与入口

- WorkBuddy 负责对话决策、模型产稿和宿主定时任务；Python 提供可重复调用、结果可判断的工具。
- 首版使用 WorkBuddy **本地定时任务**。官方说明支持对话创建任务及界面查看、编辑、暂停、立即运行和查看记录；本地执行需要客户端运行、电脑开机且不休眠并联网，不能承诺关闭客户端或关机后仍可出报。云端任务不能读取本机文件，不适用于当前取数方案。来源：[WorkBuddy 定时任务](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)、[腾讯云 WorkBuddy 说明](https://intl.cloud.tencent.com/zh/document/product/1316/84500)。
- 只使用运行时实际可见且已核对参数的宿主工具；没有相应工具时提供界面操作引导并保持待核验，不直接修改宿主数据库。公开的 `CronCreate` 等工具与 HTTP 调度端点属于 CodeBuddy CLI 文档，不能当作 WorkBuddy Desktop 接口。来源：[CLI 工具参考](https://www.workbuddy.cn/docs/cli/tools-reference)、[CLI HTTP API](https://www.workbuddy.cn/docs/cli/http-api)。
- 模板存在、本机保存的任务 ID 或配置自述，都不等于宿主创建或回读证据；任务时间和关注群变化应更新已有绑定，避免重复注册。
- 初始化、日常运行、指定日期补跑使用同一组公共工具能力，避免每条路径各写一套采集与验稿逻辑。
- 本地网页继续只读并仅绑定 `127.0.0.1`。配置和补跑通过 WorkBuddy 对话发起；页面提供明确的下一步提示。
- 取回的聊天、引用和文档内容都是待处理数据，不能提升为宿主执行指令；沿用现有用户确认账号、关注群与权限的边界。

### 身份、覆盖与产物

- 群身份使用稳定群 ID，群名只用于展示。归档、日报和索引共同遵循这一规则，并提供旧记录迁移与重建方式。
- 关注群的生效范围需要记录。新增关注群不应被追溯为所有过去日期的采集失败；取消关注后仍保留实际已有的历史产物。
- 数据覆盖需要逐库核验；缺少必需库、解密失败或消息查询失败不得作为完整采集成功。
- 成功读取到零消息也保存采集结果及目标时间范围；“未采集”不能标注为“无对话”。
- 素材与日报分别记录版本关联。重采不清空已有报告链接；素材变化后，已有稿件仍可打开，并显示需要更新。
- 可读日报必须有实际可打开的产物链接。引文按原消息与发言人组合校验；机器检查通过不等于内容质量已经获认可。
- 报告 HTML 为基本交付，PNG 能力独立记录。浏览器缺失或截图失败要明确降级，不把没有 PNG 写成已有 PNG。

### 状态与接口

启动阅读服务不依赖完成初始化。静态页面及 `/api/status` 在未配置时仍可使用；其余接口返回可识别的未就绪结果。

| 状态维度 | 必须区分的事实 |
|---|---|
| 配置 | 未配置、需修复、已配置 |
| 首份日报 | 未尝试、执行中、可读、无消息或素材不足、失败 |
| 宿主任务 | 未登记、待核对、已回读、登记或核对失败 |
| 真实定时运行 | 尚未观察、执行中、成功、失败 |
| 每群每日采集 | 未采集、进行中、成功有消息、成功零消息、失败 |
| 每群每日日报 | 待生成、生成中、可读、需更新、素材不足、失败 |

这些维度不压成一个“初始化完成”布尔值。接口共享稳定群 ID、目标日期、素材/报告版本、产物链接、最后运行结果与计划信息；计划时间来自配置和宿主回读，前端不硬编码。

错误结构至少包含 `code`、`retryable`、`next_action`，并有面向用户的说明。错误和运行日志保留定位所需信息，不记录密钥或原始聊天正文。状态接口只暴露阅读所需内容。

### 分发与升级

- 原始导入区保持不变，且继续被 Git 忽略。正式源码只从经过检查的技能文件晋升，不复制整个备份工作区。
- 出包采用逐文件白名单，覆盖前端、入口、依赖声明与引用资料；未知文件、缺少必需文件、版本不一致都阻断构建。
- 对最终 ZIP 解压后重新核验清单与内容。隐私检测覆盖 HTML、CSS、SVG 等文本资产，不能只扫描 Python 和 Markdown。
- 配置、密钥、解密快照、归档、日报和运行日志均在包外；迁移前备份，失败保留旧版可恢复状态。
- 依赖检查验证所需能力，不仅判断可执行文件存在。主线依赖与语音、图片处理等可选能力分开说明。

## 测试决定

### 主要验证入口

以 WorkBuddy 对话会调用的公共 CLI 为主入口，贯穿指定群/日期、采集归档、验稿、渲染和登记；网页通过真实 HTTP 只读 API 验证同一批结果。只在 Windows 进程访问、宿主任务等外部边界替换为桩，避免把产品内部整条路径模拟掉。

现有 [19 项审查探查](../../tools/review-import.py) 是旧缺陷证据。T0 只建立合成夹具、探查索引和公共入口；不一次写齐 13 项失败测试。开发对应票据时，逐个缺陷先确认失败再修到通过，并形成对新行为的正向回归；不以“成功复现旧 bug”的退出码作为修复通过。测试关注用户可观察结果、数据完整性和失败恢复，不堆叠与内部实现逐行对应的测试。

### 分层验收

| 验收层 | 可以证明什么 | 不能代替什么 |
|---|---|---|
| macOS 合成数据与自动测试 | 公共工具行为、身份与版本、状态、接口、错误处理、重试、迁移和出包边界 | Windows 微信实际取数、宿主真实触发 |
| 浏览器与 Impeccable 检查 | 页面可用、可读、状态准确，正常/空/失败路径可理解，响应式与键盘交互可用 | 模型内容准确与每日自动执行 |
| 第一台 Windows 实际运行 | 当前微信版本、进程取钥、实际库及 WAL 覆盖、模型产稿、HTML/PNG、宿主任务回读与到点触发 | 另一位用户首次安装成功 |
| 第二台 Windows 干净安装 | 从最终 ZIP 开始，由另一份本机配置完成首报、调度、浏览和升级 | 日报内容对用户持续有用 |
| 用户读报验收 | 内容忠于来源、重要话题覆盖、组织方式满足需求 | 其他机器和版本兼容性 |

Windows 验收必须单列：微信/系统/WorkBuddy 版本与解释器、真实取钥、活库及 WAL、真实模型稿件与源消息核对、PNG、任务登记回读、真实到点触发、第二台机器。关机、微信未登录、缺依赖、部分库失败等情况不得显示成功；恢复方式需实际演练。上述项目当前均不因本计划编写而视为通过。

### T0：建立干净基线与共同契约

- **阻塞：** 无。
- **交付：** 晋升干净源码，统一状态/接口契约、合成夹具和测试入口；未配置时可启动网页并显示如何回到 WorkBuddy 完成初始化。
- **验收：** 源码不含本机状态；缺配置时公共工具给出明确结果，状态 API 和未配置页一致；所有参与者能从同一个已提交的脱敏基线工作。
- **分工：** T0 先由主控调度内部执行代理完成；主控负责契约与集成，内部代理分别承担未配置状态、对应页面和基线核验。T0 提交共同基线后，再创建三个可见开发对话，避免把基线准备依赖于尚未启动的对话。

### T1：可靠采集指定群、指定日期并显示结果

- **阻塞：** T0。
- **交付：** 多个关注群按稳定身份归档，网页准确区分有消息、零消息和失败；数据不完整不能伪装成功。
- **对应审查：** F01、F02、F03、F07、F09。
- **验收：** 同名群不覆盖、改名保持身份、分片发送者不串位、部分解密/查询失败阻断完整结果、零消息结果可追踪；前端与 API 状态一致。
- **分工：** 后端实现可靠采集；前端同步实现状态展示；验收方执行对应回归。

### T2：对话初始化到首份可信可读日报

- **阻塞：** T1。
- **交付：** WorkBuddy 引导确认环境、账号、目录和关注群，完成一份有来源依据的日报并在网页打开。
- **对应审查：** F04、F05、F06、F11、F12。
- **验收：** 损坏配置明确失败、包内目录不得成为运行数据落点、非交互歧义返回候选、解密失败不宣称完成、引文与发言人对应；首报状态与可打开产物一致。空日或素材不足有明确原因和可选下一步。
- **分工：** 后端与 Skill 引导为主；前端准备首报进度和失败说明。合成数据开发可提前准备，真实初始化验收需 T1 完成。

### T3：历史回看、筛选与重采后报告保留

- **阻塞：** T1。
- **交付：** 按日查看多群日报、按群回看历史、关键词结合群和日期筛选；重采后仍可读已有稿件并知道是否需更新。
- **对应审查：** F08、F10，以及统一状态的前后端联调。
- **验收：** 组合过滤无错误、日期/群路由准确、真实产物链接可打开；重采不清空已有日报，缺口、零消息与失败文案准确；新增关注群不追溯制造历史失败，取消关注保留实际产物；浏览器完成正常、空、失败和键盘流程。
- **分工：** 前端以 Impeccable 推进，后端提供查询及报告保留能力。可先用合成已产日报独立开发；关闭前须接真实 HTTP API。

### T4：定时任务与失败恢复

- **阻塞：** T2、T3。
- **交付：** 用户设定时间后，WorkBuddy 任务可创建、回读、更新且不重复；到点执行有记录，漏跑日期可查看并选择补跑。
- **验收：** 配置与宿主回读一致；目标日期规则明确；同一账号、群和日期的任务避免并发写入，重复运行不重复登记；中断或失败保留上次成功产物，并能恢复未完成流程；更新时间和关注群不产生重复任务；真实到点触发成功单独留证。本地运行条件明确；运行时工具和宿主结果未验证时保持待验收状态。
- **分工：** 后端与 Skill 定义运行记录和恢复入口，前端展示计划、最近结果和缺口，验收方组织真实 Windows 宿主检查。

### T5：干净分发、升级与第二台 Windows 验收

- **阻塞：** T4。
- **交付：** 从已集成源码生成干净 ZIP，附准确初始化、兼容范围和升级说明；私有 GitHub 源码提交、版本标签与 ZIP 建立可追溯关系；第二台 Windows 能独立安装使用。

## 不在首版范围

- 公网 SaaS、多人共用后台、跨用户数据汇集，以及面向社会用户开放。
- 网页修改配置、网页直接注册宿主任务、局域网远程访问。
- 把不同群的内容合并成一篇跨群长文；首版保留每群独立日报和多群列表。
- 自动无限补跑、未确认范围的历史全量生成，以及默认开启重型语音模型安装。
- 推倒现有前端重写、引入大型构建框架或更换阅读视觉体系。
- 对所有微信、WorkBuddy 或 Python 版本作未经验证的兼容承诺。
