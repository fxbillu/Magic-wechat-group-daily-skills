# 上下文、活跃统计与人物／话题分析

继续使用已有采集 → 冻结归档 → WorkBuddy 模型写 story.json → 验稿 → 渲染 → 本机阅读流程，不新增模型账号或网络服务。

## 搜索与群内名片

阅读器搜索可以组合关键词、稳定群 ID、出报日期与人物。人物可填当前归档中的群内名片／姓名片段或稳定用户 ID。每条结果的“查看前后文”读取同一份冻结归档，默认前 8 条／后 12 条，不将搜索关键词、作者或消息类型筛选应用于上下文。自然日旧归档保持原范围；rc.5 每日接续归档可跨午夜，返回实际 `range`，不假设消息都发生于出报日期，也不声称覆盖整段讨论。

正文与来源一起生成的搜索锚点，在重建索引后仍可使用；素材改变或无法唯一定位时提示重新搜索，不猜一个同名、同 local_id 的消息。最新采集失败但有旧成功归档时仍可读，同时明确标注。

新采集优先使用 `contact/contact_fts.db` 的 `chatroom_member_fts_v3` 群内名片，通过 `contact.id` 映射成员；缺失、失败或结构不兼容时回退通讯录备注／昵称／稳定 ID。稳定群 ID、sender_id 与 source_id 不变。默认解密会尝试该可选名片库，失败不影响核心采集；不会因此解密所有 FTS 或媒体库。旧归档称呼不自动回写，重采后才更新。

## 读取分析素材

```bash
python fetch.py analyze --chat "<稳定群ID>" --date <YYYY-MM-DD>
python fetch.py analyze --chat "<稳定群ID>" --start <YYYY-MM-DD> --end <YYYY-MM-DD> --person "<稳定用户ID或姓名片段>"
python fetch.py analyze --chat "<稳定群ID>" --date <YYYY-MM-DD> --topic "<话题关键词>"
```

这些命令只读已归档内容，不刷新微信、不重新解密、不调用模型。区间最多 366 天；每一天分别返回素材版本、统计和上下文窗口，缺归档列入 `missing_dates`。关键词／人物同时给出时按交集定位命中，窗口仍保留其他人的回复。相邻窗口合并，默认最多 200 个命中，可用 `--limit 1..500` 调整；截断以 `truncated` 标明，单条正文不裁剪。没有自动语义分类；同名人物有歧义时使用 sender_id，不把显示名匹配当唯一身份。

`complete` 仅描述所选日期是否都有可读完整素材且命中未截断，不保证现实微信消息覆盖或整个讨论被窗口覆盖。写整日日报仍须读完原归档，不能拿关键词窗口代替全文。

## story.json 可选分析字段

更新日报时，由 WorkBuddy 根据当日原文选择有意义的内容，加入 `analysis` 对象；旧稿没有此字段仍可阅读。无充分素材的栏目使用空数组，不硬凑。

```json
{
  "analysis": {
    "overview": {"summary": "一两句话讲清本次讨论的主要结论和仍待确认的事项。", "source_ids": ["message_0.db:12"]},
    "topics": [
      {"title": "对账问题", "label": "待确认", "summary": "群内确认了什么、仍有哪些分歧和待确认事项。", "source_ids": ["message_0.db:12"]}
    ],
    "followups": [
      {"title": "核对对账结果", "summary": "哪些事项仍需核对；负责人和时间仅在原文明确时填写。", "source_ids": ["message_0.db:12"]}
    ],
    "people": [
      {"sender_id": "<原归档中的稳定用户ID>", "name": "<原归档中的显示名>", "summary": "此人今天提出、解释或推动了什么。", "source_ids": ["message_0.db:12"]}
    ],
    "quotes": [
      {"who": "<原作者>", "text": "<同一条源消息的完整原句>", "source_id": "message_0.db:12"}
    ]
  }
}
```

短总述 `overview` 为一个可选对象，其他每栏最多 20 项。`username/date/source_revision` 继续绑定本次冻结素材。总述需要非空摘要与有效来源；话题和待确认事项需要标题、摘要与有效来源。`label` 为可选、最多 12 字的原文状态标签，不由代码猜测。人物需要稳定 ID、显示名及本人发言来源同时匹配；金句必须逐字、同一作者、同一消息来源匹配。旧归档的工具素材会生成确定性的 `legacy:` 来源标识，使用工具返回值，不自行编造 ID。

总览先显示实算规模、主要话题、活跃分布和待确认事项，再读完整故事线与人物／金句。前三条主要话题直接显示，其余可展开；完整活跃表和原文证据折叠，不重复在结尾堆一份话题与统计。已有 `analysis.people` 时无需再写 `highlights`，旧稿的人物高光仍作为回退。没有新分析字段时仍显示已有统计和原故事，不生成示例总述或猜测待办。

“金句”表示选择有用原文，不润色成另一句话；长消息需要转述时放进话题摘要，不冒充直接引语。人物分析只描述当日讨论中的具体行动与观点，不推断人格、动机或敏感属性，不由发言量推断工作贡献。话题分析可以写共识、争议、问题及后续线索，但不能把群内口头讨论当实际任务完成。

`check_story.py` 校验新字段的来源，渲染前也会拒绝无效分析。工具不判定摘要语义正确，仍需宿主对照全文审核。

活跃统计由程序从冻结消息计算，模型不得填数字：总条数、稳定身份发言人数、文本字数、小时分布、发言量及占比。阅读器群日详情直接显示“今日总览”；完整日报 HTML／可选 PNG 也采用总览前置，HTML 的原文证据和完整榜单可展开。PNG 保留初始可见内容，不把折叠证据默认铺满长图。分析过期或来源无效时阅读器说明原因，不当作当前结论。旧 HTML 文件不批量重写，重新生成后才使用新排版。
