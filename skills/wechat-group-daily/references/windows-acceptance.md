# Windows 首装与升级验收

这是给使用者的实测流程，当前所有 Windows 项均为**待实测**。请等维护者提供集成后的 candidate ZIP、版本、SHA-256 和本说明，再开始；本开发基线还不能用来完成产品验收。
你在自己的 Windows / WorkBuddy 上操作即可，无需把微信数据交给维护者。第一次成功和第二台独立安装分别记录。

## 先把这段交给 WorkBuddy

> 请带我验收「微信群日报」候选 Skill，一步一步来，每一步先报告结果再继续。先核对我收到的 ZIP 版本和 SHA-256，再只读汇总核心库数量、源 WAL 大小分类与稳定性（只反馈数量/分类，不输出路径）；检测到 WAL 时说明覆盖尚未核验，不删除 WAL 或绕过检查。再导入；首次在对话中调用时才进入初始化，不假设导入会自动运行。使用本机实际可用的 Python，先做能力检查；未经我同意，不安装依赖、下载语音模型、提权或改系统设置。让我本人确认微信账号、包外数据目录、关注群和每天开始执行的时间；遇到同名群必须让我选。先生成前一个完整自然日的一份独立群日报并实际打开，让我核对内容；无消息或素材不足时说明事实，由我决定改日期。随后通过你实际可用且已核对的 WorkBuddy 本地任务工具或界面创建/核对同一条任务，回读任务、时间、时区、目标日期规则和执行提示词；不要把 CodeBuddy CLI Cron 当作 WorkBuddy Desktop API。保持电脑与客户端在线，等一次真实到点触发，再核对运行记录与日报；手动试跑不能记为自动成功。最后带我检查历史浏览、失败恢复和升级保留。任何步骤失败就记录步骤、脱敏错误码和下一步，保留旧配置与日报，不反复重建任务。向维护者反馈时只给版本、脱敏状态、错误码与结果，绝不输出密钥、原始聊天、真实账号/群 ID、个人目录或完整日志。

## 第一步先核对取数覆盖风险

先请 WorkBuddy 只读汇总 Windows/微信版本、必需核心库数量，以及源 WAL 大小分类（0 字节 / 1–32 字节 / 大于 32 字节）和短间隔复查是否变化；只反馈数量与分类，不输出文件路径、密钥或聊天正文。
当前 T1 对非空源 WAL 保守拒绝，出现时报告「检测到 WAL，覆盖尚未核验」，先把脱敏结果交回维护者。不要为通过检查而删除 WAL、强行操作真实原库、只复制主库或跳过检查。
非空 WAL 可能只有 header 或 checkpoint 残留，并不证明一定有未合并内容；主库副本即使 `quick_check` 通过也不能证明没有漏消息。大小稳定也不是覆盖证明。兼容方案要等目标 Windows 诊断后再判断，当前不承诺普通已登录微信即可稳定采集。

## 首次安装：每步看到结果再继续

| 步骤 | 你需要做什么 | 预期结果 | 失败时反馈 |
|---|---|---|---|
| 1. 核对文件 | 让 WorkBuddy 比较收到的 ZIP SHA-256 与维护者提供的值，确认 candidate 版本；记录 Windows、WorkBuddy、微信、Python、Node 版本与架构 | 哈希相同，来源/版本明确；无个人配置夹带 | 哪项不符；不要继续使用哈希不符的包 |
| 2. 导入后首次调用 | 导入 Skill，在对话中说「开始初始化微信群日报」。先运行 `python -B scripts/tools/package.py --capabilities`（从 Skill 根目录），再按引导体检 | 必需能力通过；PNG/语音缺失明确降级。尚未配置时网页能提示初始化 | 能力名称、passed/failed/not_tested、错误码；不贴机器路径 |
| 3. 确认账号和目录 | 本人确认本次微信账号、包外数据目录；多账号不得猜选 | 只绑定你确认的账号，配置/密钥/数据在包外，未写入 Skill | 是否多账号、是否误选/路径拒绝；不反馈账号原值 |
| 4. 选群与取数 | 选择一个或多个群；同名群看区分信息再确认。取昨天或本人改选的日期 | 覆盖核验成功；逐群区分有消息、零消息、失败，不能把缺库说成无消息 | 脱敏群标签 A/B、日期、覆盖状态、错误码 |
| 5. 打开首报 | 让 WorkBuddy 出报，打开 HTML；你在本机对照原消息核对主要话题、引文和发言人；PNG 另记 | 每群独立可读、引文归属正确。无消息/素材不足明确显示，不能伪记首报完成 | HTML 是否打开；内容通过/需修；PNG 已出/降级/失败；不粘贴聊天或稿件 |
| 6. 创建并回读任务 | 确认每天开始执行时间与时区；核对 WorkBuddy **本地**任务详情 | 任务身份、时间、目标为前一个完整自然日、执行提示词均已回读；显示等待首次定时运行 | 已创建/待核对/失败，时间/目标规则是否一致；任务 ID 仅反馈脱敏标签 |
| 7. 真实到点运行 | 保持电脑开机不休眠、微信已登录、客户端运行且联网。等设定时刻后看任务运行记录及新日报 | 有独立的 scheduled 运行记录、正确目标日和群、HTML 可打开；这时才记自动执行通过 | 预定时刻、实际开始/结束时刻、脱敏状态和错误码；手动点运行只记手动 |
| 8. 回看与恢复 | 按日看多群、按群看历史；关键词叠加群/日期筛选。在 WorkBuddy 选择一个失败步骤重试、选定范围补跑 | 链接可读、筛选正确、旧稿保留；材料变更时提示需更新；无默认无限补跑 | 哪个页面/筛选失败；重试范围与旧稿是否保留 |

核对 ZIP 的 PowerShell 命令（把占位文件名换成收到的文件）：

```powershell
Get-FileHash -Algorithm SHA256 .\candidate.zip
```

如果未观察真实到点触发，步骤 7 填「待实测」，不能由步骤 6 或立即运行代替。
本地执行条件参照 [WorkBuddy 官方定时任务说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)。默认权限若停在等待确认，也应如实记为未完成，不擅自改成完全权限。

## 失败恢复与升级：保留旧版再试

升级和故障演练由 WorkBuddy 带领，先把正在执行的任务等到结束；临时暂停后记住原启用状态。不要删除宿主任务。

| 演练 | 预期结果 | 反馈项 |
|---|---|---|
| 微信未登录/缺必需依赖/部分库失败 | 明确失败步骤与修复指引，不能显示采集成功或零消息；原有可读日报仍能打开。使用可恢复测试条件，不删除真实原库 | 演练条件、错误码、旧稿是否保留；恢复后是否成功 |
| 漏一天或中断 | 先显示缺口，本人选择有限日期/群补跑；不中断重建所有数据，重复运行不重复登记 | 中断阶段、选择范围、恢复结果、任务是否重复 |
| 升级前 | 确认包外配置/历史位置，**只在本机**备份配置和数据、旧版程序；记录任务条数/脱敏身份/时间/启用状态 | 备份已完成/失败；不上传备份，不输出其内容 |
| 升级后 | 校验新 ZIP 的版本/哈希，替换程序后首次调用能发现同一配置；打开旧日报，生成一份新报，回读原任务并再等一次到点触发 | 配置/群/历史是否保留；任务身份/数量是否保持；新首报与新定时结果 |
| 迁移失败时恢复 | 暂停继续写入，恢复旧程序与必要的本机备份；旧日报可读、原任务恢复到原状态，无重复任务。不要直接用旧程序写新 schema | 失败步骤/错误码、回滚结果、是否需维护者协助 |
