# Windows 候选试用与升级

维护者完成开发侧必要检查后提供 **1.3.0 candidate ZIP、源码提交与 SHA-256**。你拿到包即可在自己的 Windows / WorkBuddy 上尝试；真机、定时触发和第二台安装的结果随后反馈，不是取得候选包的前置条件。当前这些结果仍为待实测。

## 先把这段交给 WorkBuddy

> 请一步一步带我试用「微信群日报」候选 Skill。先核对收到的版本与 ZIP SHA-256，导入后首次在对话中调用时进入初始化。使用本机实际可用的 Python，检查所需能力，让我确认本人微信账号、包外数据目录、关注群与每日开始时间；同名群让我选。按候选的正常流程尝试取数并生成昨天的一份独立群日报，实际打开 HTML，让我在本机核对来源；无消息时由我决定是否换日期。WAL 仅记录为待核实的覆盖诊断，不要求先解决它才尝试正常路径，也不删除 WAL 或修改原库；若工具报错则保留原结果并反馈。先不安装语音模型。首报可读后，按下方模板在 WorkBuddy 创建或更新一条本地定时任务，查看任务详情确认时间和提示词；不把 CodeBuddy CLI Cron 当成桌面任务接口。失败时报告步骤、脱敏错误码和下一步，保留已有配置、日报及任务。反馈只给版本、脱敏状态和结果，不输出密钥、原始聊天、真实账号/群 ID、个人路径或完整日志。

## 按顺序试用

| 步骤 | 操作与预期 | 失败时反馈 |
|---|---|---|
| 1. 核对并导入 | ZIP 哈希与维护者提供的一致，版本为 1.3.0 candidate；导入后在对话中说「开始使用微信群日报」 | 哪一项不符；哈希不符先重新取得正确文件 |
| 2. 初始化 | 按对话检查能力，本人确认账号、包外目录和群；未配置时网页能提示下一步 | 步骤、能力状态/错误码；不贴个人路径 |
| 3. 取数与首报 | 按正常入口采集选定日期；区分有消息、零消息与失败。HTML 可打开，你在本机核对话题、引文及发言人；PNG/语音单独记可用或降级 | 日期、群 A/B、采集状态、HTML 是否打开、内容通过/需改、错误码 |
| 4. 本地定时任务 | 用下面模板创建或更新已有任务，在任务详情确认时间、工作空间和提示词，避免重复创建 | 已建/已更新/失败，时间与提示词是否一致 |
| 5. 实际到点 | 保持电脑开机不休眠、微信已登录、客户端运行且联网；到点后查看 WorkBuddy 运行记录及日报 | 预定/实际时刻、目标日期、结果；未观察填待实测，立即运行只记手动试跑 |
| 6. 回看与升级 | 按日期看多个群、按群看历史，用关键词叠加群/日期筛选；升级前本机备份配置/数据和旧程序，升级后打开旧报、生成新报并检查原任务 | 哪个页面/筛选失败；历史是否保留、任务是否重复、恢复结果 |

PowerShell 核对 ZIP（换成收到的文件名）：

```powershell
Get-FileHash -Algorithm SHA256 .\candidate.zip
```

**WAL 诊断随尝试记录即可。** 可只读汇总核心库数量、WAL 大小分类（0 / 1–32 / 大于 32 字节）及复查是否变化，反馈数量/分类即可。检测到 WAL 时标记「覆盖待 Windows 核实」，继续使用候选正常入口；非空可能只是 header/checkpoint 残留，不能据大小判定一定有未合并内容，主库 `quick_check` 通过也不是完整覆盖证明。不要为消除提示而删除 WAL、改写原库或手工只复制主库。若正常入口明确失败，反馈该错误供维护者定位。

## 可复建的 WorkBuddy 本地任务模板

在 WorkBuddy 对话或「定时任务 → 新建」中填入；时间由本人选，已有对应任务就更新它。任务来源选择本地，工作空间选择本机安装 Skill 的可访问位置。

```text
名称：微信群日报
时间：每天 [本人选择的时间与时区] 开始执行
提示词：调用已安装的「微信群日报」Skill，读取本机已确认的账号与关注群，
为前一个完整自然日生成每群独立日报。使用已保存的包外配置与数据目录。
逐群报告成功、零消息或失败，提供实际可打开的 HTML；PNG 不可用时说明降级。
失败保留已有配置和可读日报，给出下一步；不默认补跑无限历史，不重复创建定时任务。
```

保存后查看任务详情，确认时间、工作空间、目标为前一个完整自然日和提示词一致。可以先点一次「立即运行」检查流程，再等真实到点；这两种结果分开记录。没有可用宿主工具时直接用界面操作，无需安装额外调度服务或手工改宿主数据库。任务管理与本地运行条件见 [WorkBuddy 官方说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)。

## 失败与升级

- 微信未登录、缺能力或部分库失败时，先按提示修复对应步骤；不要用空消息代替错误。旧日报应仍可打开，重试/补跑日期范围由本人选择。
- 升级前等当前任务结束，必要时临时暂停并记住原状态；备份只留本机，不上传。替换代码后应发现同一包外配置和历史，核对原任务，避免再建一条。
- 迁移失败先停止继续写入，恢复旧程序及必要备份；不要直接用旧程序写新 schema。记录恢复结果供维护者协助。
