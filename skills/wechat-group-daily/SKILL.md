# 微信群日报

> 开发基线：当前正在按 T0–T5 整理完整初始化与分发流程，尚不是可分享发行版。旧采集、初始化及调度能力仍有已记录的待修项，不能仅凭本说明宣称真实 Windows 或自动运行已通过验收。

把某个微信群某一天的消息，变成一份能读的日报。**一个群一份**，每份独立成篇。

本文档是唯一入口：定时任务唤醒后，照它从头执行到尾。不需要读源码，源码里没有比这里更多的流程信息。

> **这个包是"未初始化"状态。** 出厂不带 `config.json`——每个人的微信路径和要监控的群都不一样。
> **每次开始工作前，第一件事都是跑一遍 `tools/doctor.py`**（§0.1），它会告诉你缺什么、怎么补。

## 0. 前置约定

以下命令以本 Skill 的 `scripts/` 为工作目录；也可以用脚本的绝对路径运行。个人配置从包外用户目录发现，不依赖当前工作目录。

| 概念 | 取值 |
|---|---|
| `SKILL` | 本目录（SKILL.md 所在层） |
| `SCRIPTS` | `$SKILL/scripts`，**所有命令在此执行** |
| 数据与产物目录 | 由包外个人配置的 `paths` 决定，不要猜 |
| `$PY` | Python 解释器，见下 |

配置默认在 Windows `%LOCALAPPDATA%\WeChatGroupDaily\config.json`；可用 `WECHAT_DAILY_CONFIG` 显式指定包外文件。旧包内配置不自动迁移。

**找解释器**：开发基线使用 **Python ≥3.11**；Windows 取数及可选语音依赖的兼容范围仍需实际验证，不能由 Python 版本单独判断。
依次试 `python` / `python3` / `py -3`，先确认版本：

```bash
$PY -c "import sys; print(sys.version)"
```

装了多个 Python 时，把选中的那个**绝对路径**记下来，本次所有命令都用它。
同一个包必须始终用同一个解释器，否则依赖装在不同环境里，会以 `ModuleNotFoundError` 的形式失败。

## 0.1 每轮先自检（不要跳过）

```bash
cd $SCRIPTS
$PY tools/doctor.py
```

它查七项：Python 版本 / 依赖 / 微信是否在跑 / 配置与路径 / 密钥是否仍有效 / 解密产物是否新鲜 / 有没有浏览器。
最后三行是**结论、下一步、返回码**——按返回码决定去哪，不要凭感觉猜。

| 返回码 | 意思 | 做什么 |
|---|---|---|
| **0** | 就绪 | 直接进 §1，今天的活可以干了 |
| **10** | 缺 Python 依赖 | `$PY tools/doctor.py --fix`（自动 pip 装） |
| **11** | 还没初始化 | `$PY tools/setup.py`，见 §0.2 |
| **12** | 配置里的路径对不上本机 | `$PY tools/setup.py` 重建 |
| **13** | 配置好了但没监控群 | `$PY tools/setup.py` 选群 |
| **14** | 密钥缺失/失效 | `$PY tools/doctor.py --fix`（微信要开着） |
| **15** | 解密产物过期 | `$PY tools/doctor.py --fix`（自动重新解密） |
| **16** | 需要取密钥但微信没开 | 请用户登录微信，然后 `--fix` |

`--fix` 只做三件能自动做的事：**装依赖、取密钥、重新解密**。
它**不会改配置、不会替你选群**——那两件是人的决定。

## 0.2 初始化（自检返回 11/12/13 时才做）

```bash
$PY tools/setup.py                                    # 交互式：探测微信 → 取密钥 → 解密 → 让你挑群
$PY tools/setup.py --auto --groups "群A,群B"           # 无人值守：数据落 %USERPROFILE%\wechat-daily
$PY tools/setup.py --auto --account 1 --groups "群A,群B" --root "D:\wechat-daily"
```

向导七步一次做完：环境检查 → 定位微信 → 定路径 → 取密钥 → **全量解密** → 选群 → 定时。
首次解密约 1-3 分钟；跑完 `config.json` 就绪，数据库也是可用的，可以直接进 §1。

**无人值守（定时任务、管道、CI）必须把参数给全**：`--auto` + `--groups` + `--root`，
装了两个以上微信账号时还要 `--account`（wxid 片段或序号）。缺任何一个，向导会在非交互环境
以**退出码 2** 停下，打印出可直接复制的那行命令——它不会替你猜目录，也不会替你挑账号：
猜出来的目录往往就是"解到技能包里"，挑错的账号则是"天天出另一个人的日报"。

**选群必须由人来定。** 向导只做两件事：把候选群连同近 7 天「条/人/字/轮」摆出来，给密度最好的 3 个打 ★ 推荐；
然后等你输入编号或群名。**它不会默认选中任何群**，直接回车就是"这次先不选"。

所以如果你是在替用户跑这一步：**先把候选清单和推荐念给用户，等用户点了头再输编号**。
不要自己从推荐里挑三个填进去——监控哪个群决定了以后每天出什么，这是用户的决定。

`--auto` 也不选群：它只自动化环境、路径、密钥、解密、定时，选群仍需 `--groups`。
在非交互环境（定时任务、管道）里跑，它会以退出码 4 停下并提示改用 `--groups`。

**选不到群同样是失败**（退出码 4）——监控名单为空等于出不了任何日报，不算初始化成功。

判断选哪个群的标准：**要有人来回说话**。单人单向发布的公告群、优惠券群每天都有消息，
但永远没有故事。这一步选错了，后面每天都会白跑。

`scripts/config.example.json` 是出厂模板，**不要直接拷成 config.json 用**（paths 是空的，
命令会以退出码 6 提示你去跑向导）。向导跑完才会生成本机的 `config.json`，该文件不入版本库。

## 1. 铁律：出报前必须先重新解密

**`decrypted/` 是某一时刻的快照，不是实时数据。** 微信一直在写自己的库，快照从生成的那一刻起就开始过时。

不重新解密的后果是**安静的错误**：日报看起来完全正常，内容是两三天前的。不报错、不告警，最难发现。

所以每天出报的第一步永远是——**解密 → 再看状态 → 再采集**。逆序或不解密都算流程出错。

（**只有一种例外**：刚跑完 `tools/setup.py` 的那一次，向导第 5 步已经解过，可以直接进第 2 步。）

```bash
# 1) 从运行中的微信进程取密钥（微信必须已登录并保持运行）
$PY tools/wcdb_key_tool_windows.py extract --output "<paths.secrets>/all_keys.json"

# 2) 解密出明文库（带快照与校验，不要用其他脚本替代）
$PY tools/safe_decrypt.py --db-dir "<config.json 里的 wechat.db_dir>" \
    --keys "<paths.secrets>/all_keys.json" \
    --output "<paths.decrypted>"

# 3) 看状态：新鲜度必须是 OK
$PY fetch.py status
```

**两个参数一个都不能省**（实跑踩出来的三个 notices）：

- `extract` 不带 `--output` 会把密钥写到 `$SCRIPTS/all_keys.json`，而下游只认 `secrets/`——
  两边各存一份且互不知晓，新取的密钥永远不会被用到，还不报错
- `safe_decrypt` 的 `--keys` 默认指向包内部的 `scripts/tools/`、`--output` 默认指向包内部的
  `scripts/decrypted/`——照默认跑会把 0.8GB 明文聊天记录**倒进技能包里**
- 密钥**会漂**。同一台机器相隔九小时再取，24 把里有 3 把（都是 message 库）最后一位变了。
  （`all_keys.json` 共 25 个条目，其中 `_db_dir` 是元数据不是密钥。）
  所以这一步不是走形式：不重取，就可能在某个库上解密失败

路径都从 `fetch.py status` 的前几行原样抄，别手敲。

`status` 输出里有一行 `[数据新鲜度]`：

- 显示 `⚠ …小时前解密，超过…小时阈值` → 第 2 步没成或解得太早，**回到第 2 步**
- 显示 `⚠ 核心库在解密后又被写入过` → 解密之后又有新消息进来。**要出今天**就重跑第 2 步；
  要出**昨天或更早**则不必——见下面「闸门问哪件事」
- 没有这一行 → 正常，继续

**`fetch.py archive` 会在数据不新鲜时直接中断并返回退出码 5**（与 `export` / `stat` 同一道闸门），
这是保护机制，不是 bug。修法是回来重新解密，**不是**加 `--allow-stale` 绕过。
只有当用户明确要求"用旧数据补一份历史日报"时才加。

闸门问哪件事，取决于你要出**哪一天**：

- **出历史某一天**（`--date` 早于今天）→ 只问「这份快照盖不盖得住那天」：解密时刻晚于目标日结束就放行。
  所以每天早上解一次密，全天反复补前几天的日报都不会被拦——今天下午来多少消息，都影响不到昨天。
- **出今天 / 不指定日期** → 才看时效：解密超过 `max_age_hours`（默认 24），或核心库在解密后被写过
  超过容忍窗口（`STALE_TOLERANCE_S`，5 分钟），就拦。

后一条的容忍窗口专门用来挡"刚解完就被写"的秒级抖动：微信几乎一直在写库，窗口原先只有 1 秒，
会让你刚解完就被判过期、再解一次还是过期。**每天的流程仍是先解密再采集**，这条窗口不是让你跳过解密。

## 1.1 一天只采两次：早 8 点采昨天，晚 8 点采今天

调度就两趟（`config.json` → `collect.schedule`）。两趟的命令几乎一样，**唯一差别是采哪一天**：

| 时刻 | 采哪一天 | 命令 | 为什么是这天 |
|---|---|---|---|
| **08:00** | 昨天 | `$PY fetch.py archive --config` | 08:30 要出的就是昨天，快照只需盖住昨天 |
| **20:00** | 今天 | `$PY fetch.py archive --config --date <今天>` | 给当天留痕；次日 08:00 会用完整版覆盖同一份 |

两趟都**先做 §1 那三条命令**（取密钥 → 解密 → status），没有例外。区别在于闸门怎么判：

- **08:00**：不要求"刚解完"，只要求快照**盖住昨天**。早上解一次，白天补前几天的日报都不会被拦。
- **20:00**：目标日是今天，走"时效 + 写入"判据。**这条必须先解密**——拿早上的快照采今天，
  会因"解密已 12 小时、期间全是新消息"直接退出 5。这不是误报，是它说对了：那份快照里没有今天的内容。

**20:00 那条一定显式写 `--date`。** `archive` 不给 `--date` 时默认是**昨天**，照默认跑会把昨天的数据
重采一遍、今天一条都进不来，而且退出码 0、日志写着"已保存 N 份归档"——又一个"看起来成功"。

`--date` 取当天日期：bash 用 `$(date +%F)`，PowerShell 用 `(Get-Date -Format yyyy-MM-dd)`。

## 2. 六步流程

### 第 1 步 · 解密（见上一节）

成功标志：`status` 里数据新鲜度 OK，且 `解密到` 目录存在 24 个 `.db`。

### 第 2 步 · 确认要出哪些群、哪一天

```bash
$PY fetch.py status            # 看配置里盯了哪几个群、已归档几天
$PY fetch.py list --kind group --active --limit 20   # 需要新增/换群时看候选清单
```

群里默认取 `config.json` 的 `chats`（`daily: true` 的那些）。用户临时指定群时，用 `--chats "群A,群B"` 覆盖。

### 第 3 步 · 采集归档

```bash
$PY fetch.py archive --config --date <YYYY-MM-DD>
```

- `--date` 是**要出日报的那一天**。出"今天的日报"通常指昨天：`--date` 填昨天。
- 采哪一天见 §1.1：08:00 那趟可以省 `--date`（默认昨天），**20:00 那趟必须显式写今天**，否则重采昨天。
- 成功标志：输出 `已保存 N 份归档`，并在 `<paths.data>/<date>/` 下出现 `<群名>.json`。
- **这一步会把数据写进 `data/index.db`**（派生索引）。索引可以随时用 `fetch.py reindex` 从 `data/` 全量重建，
  它丢了不影响真相，别去手改。

### 第 4 步 · 写 story.json（唯一的模型步骤）

对每个群，读**已冻结的归档**，写一份 story.json，落在
`<paths.reports>/<date>/<群名>.story.json`。

```bash
data/<date>/<群名>.json                                     # 素材首选
$PY fetch.py export --chat "<群名>" --date <YYYY-MM-DD> --format text --allow-stale   # 备选
```

**为什么素材要用归档**：`export` 读的是实时明文库，微信一直在写，闸门会在归档之后
几秒钟就把后续命令判为过期。归档那一刻已经冻结，和 `stats` 天然对齐。
确实用 `export` 时，对**已经归档过的那一天**加 `--allow-stale` 是安全的。

**必须照 `references/writing-spec.md` 写。** 那里有完整的字段表、取材原则、禁忌清单和自检表。三个最容易踩的形状问题：

- `quotes` 是 `[{"who":"发言人","text":"原文"}]`，写成字符串数组会渲染崩溃
- `opening` 150-200 字且必须以汉字开头（首字要做 drop cap）
- 每段 `story` 150-250 字，说的人和引用的话必须能对上归档

取材的三条硬规矩（详细版在参考文档）：

- 形态照 vchat 的 `group-daily`：开场叙述 + 故事线 + 人物卡 + 收尾金句
- **段数按话题划，不按配额**：一件事一段，至少 3 段，不设固定上限。
  每段背后至少要有 60 字真实素材——够就写，不够就别硬撑
- `story` 按时间顺序把谁说了什么转述出来；`quotes` 一个字不改
- `highlights` 选"没他故事就少一块"的人，**不是发言量排名**；禁止一切图表与排行

**素材不够的群跳过，不硬凑——但判据不是条数。** 拿不准先让工具摆数据：

```bash
$PY tools/check_story.py --assess "<群名>" --date <YYYY-MM-DD>
```

它给条数 / 人数 / 字数 / 对话轮次，**不下结论**。真正的地板只有两条：文字总量不到 200 字，
或者一个人单向发布、无人接话、又不到 800 字。命中任一条就不出报，直接告诉用户原因
（"10 条全是同一个号发的优惠券，没有一句对话"）。

其余情况**先读完再判**。一个人贴几段长文讲清一件事，条数再少也是好素材；
一个群刷了一百条"哈哈哈"，条数再多也没东西可写。读完划不出 3 段完整故事线（`material.MIN_NODES`），才叫不够成篇。

**写不出来就明确失败。** 不要产出一份凑合的稿子——降级的日报会让人以为今天就是这样。

### 第 5 步 · 机器自检 + 渲染登记

```bash
$PY tools/check_story.py "<paths.reports>/<date>/<群名>.story.json"   # 不过就改，别跳过
$PY tools/render_daily.py "<paths.reports>/<date>/<群名>.story.json"
```

自检工具查的是引号逐字、字数区间、cast 有效性、`stats` 一致这类机械项——它查不了故事线划得对不对，
那部分还得自己过 `writing-spec.md` 第六节。

渲染产出同目录下同名 `.html` 与 `.png`，并登记到索引。主题取 `config.json` 里这个群的
`theme`（出厂都是 `magazine`），临时想换用 `--theme`。**默认主题 `magazine`，没有特别理由不改。**

成功标志：输出 HTML/PNG 路径，且 `fetch.py views` 里该格不再是 `pending`。

### 第 6 步 · 核对

```bash
$PY fetch.py views
```

三个视图是同一份数据的三种切法：当日总览 / 群时间线 / 全景矩阵。

当日总览里每行一个状态，看状态就知道该不该动手：

| 状态 | 含义 | 要不要管 |
|---|---|---|
| `ready` | 已出报 | 不用 |
| `pending` | 有归档、素材也够，**欠一份日报** | 要，这是真欠账 |
| `empty` | 有归档、但素材不足成篇 | 不用，后端已算好并给出理由 |
| `missing` | 配置里监控，当天连归档都没有 | 要，采集很可能断了 |
| `orphan` | 有产物无归档 | 要，`data/` 可能被清过 |

**`empty` 不是失败**，是这天的群本来就没东西（公告群天天如此）。真正要盯的是 `pending` 和 `missing`。

浏览：

```bash
$PY tools/serve.py            # 只绑 127.0.0.1，本机可看
```

前端是 `scripts/web/` 下的单页应用（Vue 3 本地单文件，无构建链，改完刷新即见），
状态来自 `/api/status`，日报读取使用本地只读 API。开发时按仓库的读取契约和视觉基线修改；发行包不依赖旧工作区的 `SCHEMA.md`。
**改前端不要动 `render_daily.py`**——日报页要靠静态渲染截长图。

**不要把服务绑到 `0.0.0.0`**：解密产物是明文聊天记录，同一 WiFi 下谁都能访问。手机端将来走飞书云文档，不走端口。

## 3. 出问题怎么定位

按从上到下的顺序查，每步都有明确的"断在哪"信号。

| 现象 | 断在哪 | 怎么办 |
|---|---|---|
| 退出码 **6** + `尚未初始化` | 这台机器还没跑过向导 | `$PY tools/setup.py`，别手写 config |
| `No module named wechat_data` | 工作目录不对 | 回到 `$SCRIPTS` 再执行 |
| 退出码 **4** + `请先运行 …extract + decrypt` | 没解密，`decrypted/` 是空的 | 跑第 1 步 |
| 退出码 **5** + `数据不新鲜` | 快照过期 | 重新解密，**不要**用 `--allow-stale` 绕过 |
| 退出码 **3** + 会话名有歧义 | 多个群同名或名字部分匹配 | 用完整群名，或改用群 id |
| 退出码 **2** + `无法在非交互环境继续` | 向导缺参数（`--root` / `--account`） | 照它打印的那行命令补上参数重跑 |
| 退出码 **2** + 归档数为 0 | 步骤没跑完（未归档/未保存） | 看上一条输出缺了哪个群 |
| `status` 报配置文件路径不存在 | 配置搬过家 | 跑 `tools/setup.py` 重建 |
| 日报出得来但内容明显是旧天的 | 第 1 步被跳过 | 回第 1 步，看新鲜度那一行 |
| HTML 出来了但 `views` 里没有 | 渲染时没登记 | 重跑渲染（不要加 `--no-register`） |
| PNG 生成失败 | 浏览器缺失 | 先交 HTML；这是已知降级路径 |
| `AttributeError: 'str' object has no attribute 'get'` | `quotes` 写成字符串数组了 | 改成 `[{"who":…,"text":…}]` |
| 刚归档完，`export` 立刻报数据不新鲜 | 微信又写了库，闸门正常触发 | 读 `data/<date>/<群名>.json`，或加 `--allow-stale` |
| 换了机器/重装后全部解密失败 | 密钥过期或路径没指到 `secrets/` | 重跑第 1 步，确认 `--output` 落在 `secrets/` |

`tools/doctor.py` 会依次检查 Python、依赖、微信进程、配置路径、**密钥（第 [5] 项）**、解密产物、浏览器与 Node。
密钥有效性需要逐库校验；库数量以本人账号实际发现的库为准，不能固定为旧机器上的数量。

---

## 4. 不做的事

- **不做跨群汇总。** 一个群一份日报，不把几个群揉成一篇"今日总览"。
- **不做发言排行、不画 24 小时曲线、不做话题分布图、不做 Dashboard。** 这些是这套模板明确摒弃的东西。
- **不删日报。** 归档会按保留天期满后清理采集层数据（`retention.data_days`），但已出的日报只增不减。
- **不为凑段数而拆段。** 一件事一段；段数由话题决定，每段至少 60 字真实素材。
- **不改文风去追求"像人写的"。** 要求是把事转述清楚，不是把句子写漂亮。
- **不猜。** 数据不新鲜就停，写不出 story 就报失败，别产出看着正常实则错的东西。

---

## 5. 只查不出报

用户问"这个群昨天聊了什么"但没要日报时，走到第 3 步就够了。素材读冻结的归档
`data/<date>/<群名>.json`，确需命令行导出时：

```bash
$PY fetch.py export --chat "<群名>" --date <YYYY-MM-DD> --format text --allow-stale
$PY fetch.py stat   --chat "<群名>" --date <YYYY-MM-DD> --allow-stale
```

（那天若已归档，`--allow-stale` 是安全的——读的是当日快照，不涉及新数据。）

不落 HTML、不写 story、不占 `reports/`。

## 6. 已知边界

- **语音消息目前只有 `[语音]` 占位**，没有转文字。`lib/wechat_data/voice.py` 有转写实现，
  但主链路还没接进去，归档里只能看到"有条语音"，不知道说了什么。
- **解释器没有写进配置**，靠调用方每次指定同一个。换机后先确认 Python ≥3.11。
- **`config.json` 里存的是绝对路径**，所以"整体搬走"指的是搬**数据**；包本身搬到新机器后
  要重跑 `tools/setup.py` 重新生成本机配置。
- **`--auto` 的数据落点默认是 `%USERPROFILE%\wechat-daily`**，不是技能包目录。技能包里长不出
  `decrypted/`（明文聊天记录）和 `secrets/`（明文密钥）——包要能被拷来拷去。
- **定时任务里必须给全参数**：`--auto` + `--groups` + `--root`（多账号还要 `--account`）。
  缺任何一个，向导会在非交互环境以退出码 2 停下并打印可复制的命令，不会默认一个值糊过去。

这些是这一版的真实边界，没有藏在文档外。
