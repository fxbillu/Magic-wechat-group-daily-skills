# 变更记录

## 1.2.0 — 2026-10-26

### 浏览台从前端直出改成「SPA + JSON 接口」

`tools/serve.py` 从"服务端拼 HTML 字符串"改成"静态托管 + `/api/*`"。新增
`scripts/web/`（`index.html` / `app.js` / `app.css` / `vendor/vue.global.prod.js`，
Vue 3.5.44 单文件本地加载，无构建链、无 CDN、无 `node_modules`）。
路由改由 History API 驱动，后端对无扩展名路径回落 `index.html`，带扩展名却不存在就老实 404——
否则写错一个资源路径，浏览器会把 HTML 当 JS 解析，报一堆看不懂的语法错。

契约同步升级到 **SCHEMA v1.2**，按「字段只增不改」加了四个东西：

| 新增 | 为什么 |
|---|---|
| `/api/browse` 的 `recent` | `today` 只有最近一天，撑不起首页 3/7/14/30 天切换 |
| `/api/browse` 的 `dayrows` | 日期轴的计数必须来自全量索引，拿只覆盖 30 天的 `recent` 画整条轴，第 31 天会显示成「0 个群」 |
| `/api/search` | `db.search()` 早就实现了，只是一直没开路由 |
| `/api/messages` | 明细页要看原始记录，一天几千条的群不能一次拉全量 |
| `matrix.cells[].state` | 单元格只有 `{total, ready}` 时推不出 `empty` |
| `chats[].last_state` | 群列表原来用 `reports>0 ? ready : total>0 ? pending : missing` 自己推，`empty` 永远被推成 `pending` |

### 修掉两个「第五态看不见」的真 bug

这两个是同一类错误的两处实例：**前端拿散装字段自己拼状态**。

1. **矩阵格里 `empty` 显示成消息数**。`db.matrix()` 只给 `{total, ready}`，
   `empty`（有归档、素材不足）退化成"有数字但没出报"，和 `pending` 长得一样；
   而矩阵是唯一能一眼看全五态的视图，等于第五态在那儿根本不存在。
   现在单元格直接带 `state`，复用 `_state()`，不再另写判定。
2. **群列表把 `empty` 画成 `pending`**。`像素蛋糕` 两天 6 条、0 份日报，
   列表给的是"有数据未生成"（欠一份），真相是"素材不足，未成篇"（不欠）。
   现在后端给 `last_state`。

### 首页状态条的群数被数了两遍

`today.chats` 已经含 `missing` 的群（`by_day(include_configured=True)`），
原来又加了 `t.missing`，出现「3 个群中 2 个有归档」而实际只有 1 个。
现在分母 = 关注名单 ∪ 当天有归档的群，分子 = 真的有的。

### 矩阵：结构性空白不再冒充空洞

采集起点之前的日子原先一天一列、整列都是 `·`，十列长得一模一样，
把真正的洞埋掉了。现在：

- 整列无归档的列**不出符号**，只留一条纸带（`paper-sunken`），
  和「这个群这天没归档」（`·`）区分开——前者是采集边界，后者才是个别的洞
- 开头那段空白**压成一列**，表头写日期区间（`10-13–10-22`）；
  区间内部的断更不压，一天都得看见
- 群名列 `position: sticky; left: 0`，横向滑动时钉住

### 卡片：没有长图就不摆缩略位

900px 宽的日报缩到 92px，标题只剩 3px 高，那张图从来读不出内容。
它的作用只是让"成篇了"有体积——所以没成篇的卡片不再摆一个等大的灰框（写着"无日报"），
直接塌成两行紧凑卡。一天的 5 张卡里，唯一那份日报现在明显更重。

### 明细页：长图改用 `<img>`

原先用 `<iframe>` 看日报，一份 5857px 高的报告被裁在中间，页面里还套了第二根滚动条，
看不出是没画完还是没滚。现在 `<img>` 跟着页面滚；`orphan`（有产物无归档）也照样显示，
只是先给一条红框警告。

### 其它

- 装饰色（`ink-decor` / `ink-whisper` / `ink-veil`）不再用于任何文字：消息类型标记
  和搜索框占位符改 `ink-muted`（原来 4.43:1 和 1.98:1，都不过 4.5）
- 搜索高亮加 2px 底线：`pending-surface` 和暖纸底只差 1.05:1，纯底色读不出来
- 23 处行内 `style=""` 收进 `app.css`；遮罩色用 `color-mix(in srgb, var(--ink) 28%)` 算，不引入调色板外的颜色
- 帮助浮层打开时锁背景滚动；`:focus-visible` 用真 Tab 键验证通过（脚本 `.focus()` 测不出来）
- 新增 `DESIGN.md`（15 条具名规则 / 15 个组件令牌）与 `.impeccable/design.json` 边车

## 1.1.5 — 2026-10-26

### 调度收敛为早晚各一次，并修掉「采今天永远被拦」

采集时段定为 **08:00 / 20:00**（`config.json`、`config.example.json`、向导默认值三处一致）：
早 8 点采昨天（08:30 出报用），晚 8 点采今天（当天留痕，次日 08:00 用完整版覆盖同一份）。

`archive` 不给 `--date` 时默认是昨天，所以 20:00 那趟必须显式写今天，否则会把昨天的数据
重采一遍、今天一条都进不来，退出码却是 0。SKILL.md 新增 §1.1 把这条写成硬要求。

**同时修一个真 bug**：`guard.check(target_date=今天)` 也走了「快照要盖住那天」的判据，
而"今天"这一天没过完，`解密时刻 ≥ 该日结束`永远不成立——结果是**任何以今天为目标的采集都返回 5，
哪怕刚解密**。1.1.4 的用例只验了「出今天应被拦」的期望值，把这条错误判据验成了正确。
现在覆盖判据只管**早于今天**的日期；今天/未指定仍走时效 + 写入判据。

## 1.1.4 — 2026-10-26

### 修复：闸门判据错位——历史日期改问「快照盖不盖得住那天」

1.1.3 把闸门接上后，判据是「解密之后微信有没有再写过」。这对**出今天**是对的，
对**出昨天**是错的：早上 7:55 解出来的快照对昨天是完整的，今天上午来一百条消息也影响不到昨天。

按实际调度（每天定时解密一次、采集 08:00/14:00/20:00、出报 08:30），旧判据会让 14:00 与 20:00
两次采集直接退出 5——1.1.3 单独上线会打断每天的后两次采集。

现在 `guard.check()` 支持 `target_date`：

- **历史日期**（早于今天）→ 只问「解密时刻是否晚于该日结束」。是则放行，否则拦住并明说
  「解密于 …, 早于 … 结束，覆盖不到那一天」。
- **今天 / 未指定** → 仍走时效 + 写入判据（24 小时 / 5 分钟容忍窗口）。

`archive` 用 `_date_list()` 的最大日期作目标日（`--days` / `--start` 一并适用）；
`export` / `stat` 用 `--date` / `--start` / `--end`，都没有则不按日期判。

实测：早上解密(1h 前)出昨天且期间有写入 → 放行；解密于 3 天前出昨天 → 退出 5；
出今天且解密后有写入 → 退出 5；真实仓库解密于今天 14:31，`export --date` 昨天 → 放行（1.1.3 下被拦）。

## 1.1.3 — 2026-10-26

来源：对 HANDOFF §3 的独立核查。六条全部是**实测出来的**缺陷，不是新功能；共同点是
「看起来正常，实际错了」——退出码 0、日报长得对、内容却是错的。

### 修复：archive 没有新鲜度闸门（主链路裸奔）

`fetch.py archive` 是出日报的第一步，却**唯一**没接闸门：数据过期时照常归档、退出码 0，
下游拿着几天前的快照写稿渲染，日报看着完全正常。而 SKILL.md §1 一直宣称它会返回 5。

现在 `archive` / `export` / `stat` 共用 `_check_freshness()`：过期 → 退出码 5，
`--allow-stale` 才放行（`archive` 也接受这个参数了）。`guard.assert_fresh()` 从零调用变成实际入口。

### 修复：闸门 1 秒容忍窗口 → 5 分钟

微信几乎一直在写 `message` / `session` 库，解密结束后十几秒来一条消息，整份快照就被判过期。
实测：14:24:39 解密完成，`message_2.db` / `session.db` 在 14:24:55 被写 → doctor 立刻返回 15。
按文档"回第 2 步"会陷入"重解→仍判过期"的循环。

`guard.STALE_TOLERANCE_S = 300`（`check()` 可用 `tolerance_s` 覆盖）。5 分钟对以天为粒度的日报没有影响。

### 修复：`--auto` 把 847MB 明文解进技能包

`--auto` 未给 `--root` 时 `root = BASE`，而 BASE 就是 `scripts/`。实测："一键初始化"后
技能包从 117KB 涨到 848MB（847MB 明文聊天记录 + 24 把明文密钥），拷给谁就等于把聊天记录拷给谁。
现在默认落 `%USERPROFILE%\wechat-daily`，并在第 [3/7] 步打印明文/密钥/归档/日报四个落点。

### 修复：setup 在非交互环境崩栈 / 静默选账号

- 三处裸 `input()` 没有任何 EOF 保护，`--groups "群A,群B" < /dev/null` 直接抛 `EOFError`、退出码 1、
  配置一个字没写。现在统一走 `ask_required()` / `ask_default()`，缺必填参数时**退出码 2** 并打印可复制命令。
- 本机有 2 个微信账号时，`pick_account()` 在 EOF 下**静默返回第 1 个**，什么都不打印。
  选错账号不是报错，是天天出另一个人的日报。现在多账号必须 `--account`（wxid 片段或序号），
  交互模式回显所选项并要求确认。
- 注意 Windows 上 `< /dev/null` 映射到 `NUL`，是字符设备，`isatty()` 会误报成终端，
  所以"没人应答"只能靠 EOF 兜住，不能只信 `isatty()`。

### 修复：配置里的 `theme` 是死的

`config.json` 一直写着 `chats[].theme`，渲染层却只认命令行 `--theme`，那个字段写了等于没写。
现在取值顺序：群的 `theme` → `compose.theme` → `magazine`；命令行仍可临时覆盖。

### 文档与代码对齐

- 段数地板：SKILL.md 与 `writing-spec.md` 的"划不出 **6** 段"改为 **3** 段（`material.MIN_NODES`）
- 密钥条数：SKILL.md 的"25 条"改为"24 把（第 25 个条目是 `_db_dir` 元数据，不是密钥）"
- 删掉 SKILL.md §3/§6 那条过时说明（"doctor 第 [2] 步读旧密钥路径、显示未知"）——
  实际是第 [5] 项、读 `secrets/all_keys.json`、显示 24/24
- Python 门槛统一为 3.11（`setup.check_env()` 原为 3.10）；`doctor.py` 注释"六关"→"七项"
- `setup.py` 横幅顺序改为与实际执行一致；补 `--account` 用法

## 1.1.0 — 2026-10-26

让技能**自己检查自己要不要初始化**，并且**把选群的决定权交回给人**。

### 新增：`tools/doctor.py` 成为每次工作的第一入口

原来没有配置时，是"跑任何命令被退出码 6 拦下，再自己想办法"。现在是先体检：

```bash
$PY tools/doctor.py          # 七项检查，结论 + 下一步 + 返回码
$PY tools/doctor.py --fix    # 自动补：装依赖、取密钥、重新解密
```

七项：Python 版本 / 依赖 / 微信是否在跑 / 配置与路径 / 密钥是否仍有效（逐个库校验）/
解密产物是否新鲜 / 有没有浏览器能出 PNG。

返回码分级（10-16），上层按码决定跳哪一步，不用读中文猜：

| 码 | 含义 | 能自动修吗 |
|---|---|---|
| 0 | 就绪 | — |
| 10 | 缺依赖 | `--fix` pip 安装 |
| 11 | 未初始化 | 不能，要人跑 `setup.py` |
| 12 | 配置路径对不上本机 | 不能，要人重跑 `setup.py` |
| 13 | 没有监控群 | 不能，要人选 |
| 14 | 密钥失效 | `--fix` 重新提取（微信需运行） |
| 15 | 解密产物该刷新 | `--fix` 重新解密 |
| 16 | 要取密钥但微信没开 | 不能，要人开微信 |

`--fix` 刻意**不碰配置、不选群**——那两件是人的决定。

顺带修掉这个脚本一直以来的毛病：密钥路径和解密路径还是搬迁前的硬编码
（`tools/all_keys.json`、包内 `decrypted/`），所以第 [2] 关永远显示"未知"。
现在全部走 `settings`，并按 `paths.root` 的父目录是否存在判断"这份配置是不是别处带来的"
（补上 1.0.0 遗留的路径存在性校验，返回码 12）。

### 改变：选群不再有默认值

`tools/setup.py` 原来在两处替用户做了决定：`--auto` 直接取密度前 3；
交互时直接回车也是"默认前 3 个"。现在都去掉了：

- 候选清单照旧打印近 7 天「条/人/字/轮」，并给密度最好的 3 个打 **★推荐**（只打星，不选）
- **回车 = 这次先不选**，不会偷偷填三个群进去
- `--auto` 只自动化环境/路径/密钥/解密/定时，选群仍需 `--groups`
- 非交互环境（定时任务、管道）不会瞎选，而是以**退出码 4** 停下并提示改用 `--groups`

理由：监控哪个群决定了以后每天出什么，这是用户的判断。
工具该做的是把候选和画像摆清楚，不是替人拍板。

### 文档

`SKILL.md` 重写开头两节：§0.1「每轮先自检」给了返回码对照表，
§0.2「初始化」明确写了"如果你在替用户跑，先把候选和推荐念给用户，等点头再输编号"。

## 1.0.0 — 2026-10-26

首个可交付版本。**这个版本是"未初始化"态**：不带 `config.json`，第一次用要先跑 `tools/setup.py`。

### 能做什么

一条链路跑通：本机微信加密库 → 解密 → 按群按天归档 → 写一份叙事日报 → 出 HTML/PNG → 本机浏览。
一个群一份，不做跨群汇总。

### 主要构成

| 位置 | 作用 |
|---|---|
| `SKILL.md` | 唯一入口，定时任务照它执行 |
| `references/writing-spec.md` | 写稿规范（字段、取材、禁忌、自检） |
| `scripts/fetch.py` | 采集/归档/查询/视图 |
| `scripts/lib/wechat_data/` | 配置、消息解析、索引、渲染、素材判定 |
| `scripts/tools/setup.py` | 初始化向导 |
| `scripts/tools/safe_decrypt.py` | 稳定快照解密（带时间戳闸门） |
| `scripts/tools/check_story.py` | 稿件机械自检 + 素材画像 |
| `scripts/tools/render_daily.py` | 出 HTML/PNG 并登记索引 |
| `scripts/tools/serve.py` | 本机浏览（只绑 127.0.0.1） |
| `scripts/tools/package.py` | 出厂审计与打包 |

### 这一版的设计决定

- **出厂不带配置**：未初始化时所有命令以退出码 6 停下并指路，绝不拿包内默认路径开工
  （否则会把明文聊天记录写进这个要拷来拷去的目录）。
- **素材够不够不看条数**：看文字总量与对话轮次。一个号连发十条促销不是故事，
  一个人贴几段长文可能是。地板值集中在一处（`material.py`）。
- **段数不设固定区间**：至少 3 段、按话题划，每段至少 60 字真实素材。今天只有 3 件事就写 3 段。
- **选群时就该判断**：`setup.py` 打印每个候选群近 7 天的「条/人/字/轮」，
  自动模式按对话轮次排序，不让高频广播号靠刷新时间赢。
- **失败要能看出断在哪**：数据过期退出码 5（不静默用旧数据）、缺库 4、未初始化 6、会话歧义 3。
